# ☁️ AgentProxy 子系统设计规范 (CLAUDE.md)

## 🚀 模块总览
AgentProxy 是系统级的通用状态和事件的**中央独立数据接收网关 (Central Independent Data Ingestion Gateway)**。它的核心职责是提供一个稳定、高可靠性的数据接入点，用于接收来自所有离散、非实时、异步的系统级状态报告和通用事件。

**关键原则**:
1.  **完全独立**: AgentProxy 的所有功能和数据写入流程必须是自给自足的。它不主动调用任何业务服务，也不应依赖于任何特定业务模块（如 `backend` 的业务流程）的实时调用结果。
2.  **职责聚焦**: 它只负责接收、校验、结构化和持久化数据，是系统的**审计和状态记录器**。
3.  **数据来源**: 数据主要来自独立的定时任务、监控系统、外部批处理作业等，通常是异步或批量上传。

## 🛠️ 架构约束与实现细节
*   **API 框架**: 使用 FastAPI 实现所有路由。
*   **持久层**: 采用 简单.log 风格，上下文管理器。
*   **数据操作**: 所有数据操作必须设计为能接受批处理 (Batch) 或异步 (Async) 写入模式，从而适应来自外部独立系统的调用特点。

## 📩 核心 API 接口规范
该服务需要提供所有外部系统能够报告其通用状态的通用接口。

*   **认证**: 所有请求必须通过一个系统级的、强制认证依赖 (`Depends(get_system_auth)`)，以确保数据源的可信度。
*   **主要接口**: 至少应提供两个核心接口：
    1.  `/api/v1/status`: 测试接口简单测试服务接口是否可以访问（通过get方法，获取`Alive`的字符串就可以）。
    2.  `/api/v1/logs/event`: 用于接收通用、结构化的系统事件或审计日志。

## 🧱 模块依赖链 (仅为数据结构参考)
本模块的逻辑和数据结构主要由以下文件定义和依赖：
1.  **`database.py`**: 负责数据库引擎和连接管理。
2.  **`models.py`**: 包含所有系统级模型（`Component`, `TelemetryLog`），这些模型定义了系统可以记录的通用数据结构。
3.  **`endpoints.py`**: 包含核心路由逻辑，负责业务数据的请求处理、验证和事务提交。
4.  **`main.py`**: 负责应用的初始化、路由挂载和 ASGI 服务器启动。

## 编码规范
*   **说明的注释**:
    1. 需要包含输输入，输出，功能说明，数据示例等信息
*   **代码脚本整体结构如下：**:
    1.  类库引用全部要放到脚本最头部位置，避免重复引用，以及无效引用。
    2.  全局变量声明放到脚本其次的位置。
    3.  函数声明再次位置。需要包含函数
    4.  主函数最后。


## 🚀 服务启动指南
**运行命令**:
```bash
python .\main.py
```
**说明**: 优先使用。应在项目根目录或包含 `main.py` 的目录下执行。
```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```
**说明**: 这是一个使用 Uvicorn 启动 FastAPI 应用的命令。应在项目根目录或包含 `main.py` 的目录下执行。
